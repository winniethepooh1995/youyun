# 個人資料搜尋入口：模擬資料原型

日期：2026-10-11

## 目的與範圍

建立僅供使用者自己體驗的繁體中文網頁原型。在同一個入口搜尋模擬 Outlook 郵件與 Google Drive 文件，先查看結果，再取得附來源的模擬整理摘要。成功標準是使用者能從一個主題找到兩種來源的相關資料、閱讀內容，並追溯摘要依據。

正式 Outlook 與 Google Drive 均為公司帳號，串接、內容索引的保存位置及外部 AI 使用須待 IT 確認。原型不登入公司服務、不讀取真實資料、不呼叫外部 AI、不需要 API 金鑰。模擬整理功能在畫面明確標示為示範，不宣稱具備真實模型推論能力。

## 使用流程與畫面

採單頁、可在桌面及手機瀏覽的介面。頂部顯示名稱、模擬資料提示及搜尋框，提供可點選的範例搜尋。初始畫面列出全部資料；輸入關鍵字或問題並提交後顯示相關結果與筆數，可按來源篩選全部、Outlook、Google Drive。

每筆結果顯示來源、標題、日期及內容摘要。點選結果開啟內容面板，呈現完整內容及郵件寄件者或文件作者。模擬資料沒有真實外部連結；來源連結開啟原型中的對應內容。

「AI 整理（模擬）」對目前顯示的搜尋結果整理重點，每點附來源編號，點選編號可開啟相應資料。重新搜尋或切換來源時清除舊摘要，避免結果與引用不一致。沒有結果時顯示搜尋建議並停用整理按鈕。關閉內容面板可回到結果；面板支援鍵盤關閉及基本焦點管理。

## 模擬資料

提供 20 筆合成資料，Outlook 與 Google Drive 各 10 筆。資料涵蓋會議、報價、專案進度、出差四個主題；每個主題都包含兩種來源，並具備可用於摘要的具體日期、金額、待辦或狀態。全部人物、公司與內容均為虛構。

共同欄位為唯一 ID、來源、標題、日期、作者、完整內容、主題關鍵字及預先撰寫的整理重點。資料保存在專案的本地靜態模組，不建立資料庫、不保存個人資訊或搜尋歷史。

## 技術設計與資料流

使用 React、TypeScript 與 Vite，透過 Node.js 開發伺服器啟動並建置靜態網頁。沒有後端與登入流程。

分離資料模組、搜尋與摘要純函式、畫面元件。搜尋以標題、內容與主題關鍵字進行本地比對，正規化空白與英文大小寫，以主題關鍵字對照支援範例問句。標題與關鍵字命中的排序優先於內文，平手依日期由新至舊。這是可預期的示範搜尋，不是語意向量搜尋；任意自然語言問題可能無法命中。

整理函式從目前結果的預寫重點產生摘要，最多取前五筆並保留各自來源 ID。不得加入資料沒有的事實或引用未顯示的資料。介面清楚說明此功能使用預先撰寫的重點，不呼叫真實 AI。

## 錯誤與無障礙

空白搜尋回到全部資料；無符合結果時提供可執行的範例。資料以文字渲染，不注入 HTML。按鈕與輸入有可辨識標籤，操作可透過鍵盤完成，來源不僅靠顏色區分。正常使用不依賴外部資源或網路請求。

## 驗證與完成標準

1. 建置與 TypeScript 檢查通過。
2. 搜尋測試涵蓋跨來源主題、無結果、空白查詢、英文大小寫與來源篩選。
3. 摘要測試確認每個引用皆來自當前結果、無結果不產生摘要，以及只使用已有重點。
4. 在開發伺服器驗證：搜尋「專案進度」可找到兩種來源；查看內容可正常開啟及關閉；整理後的引用可開啟對應資料；重新搜尋後清除舊摘要。
5. 驗證手機寬度的結果與內容面板，以及鍵盤操作。

## 後續工作邊界

真實 Microsoft Graph、Google Drive OAuth、權限管理、資料同步、持久化索引及真實 AI 均不包含在本原型。IT 回覆後另行設計正式版本。雲端開發使用既有 /workspace/youyun checkout，不另建 Git worktree；完成實作後保存已驗證的安裝與啟動設定。
